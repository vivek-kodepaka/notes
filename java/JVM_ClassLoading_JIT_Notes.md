# JVM Class Loading, Method Bytecode, and JIT Compiler -- Complete Notes

## 1. Overview of Execution Flow

Java program execution happens in these steps:

1.  Java source code (.java) is compiled using `javac`
2.  Bytecode (.class) is generated
3.  JVM loads the class using ClassLoader
4.  Class metadata and method bytecode are stored in Method Area
    (Metaspace)
5.  Execution Engine runs methods using Interpreter
6.  Frequently executed (hot) methods are compiled by JIT into native
    code

------------------------------------------------------------------------

## 2. How Class Loading Works

When you run:

    java MyApp

The JVM uses the **ClassLoader subsystem**.

### Steps in Class Loading

#### Step 1: Loading

-   ClassLoader reads the `.class` file
-   Bytecode is brought into memory

#### Step 2: Linking

Linking has three sub-steps:

1.  Verification
    -   JVM checks bytecode safety and format
2.  Preparation
    -   Memory allocated for static variables
3.  Resolution
    -   Symbolic references replaced with actual references

#### Step 3: Initialization

-   Static variables assigned values
-   Static blocks executed

------------------------------------------------------------------------

## 3. What Gets Stored in Method Area (Metaspace)

When a class loads, the following are stored:

-   Class metadata (name, parent, interfaces)
-   Method definitions and bytecode
-   Static variables
-   Runtime constant pool

Important: Objects are NOT stored here. Objects are stored in Heap.

------------------------------------------------------------------------

## 4. How Method Bytecode Is Loaded

Example:

``` java
class Calculator {
    void add(int a, int b) {
        System.out.println(a + b);
    }
}
```

When this class loads:

-   Method signature stored in Method Area
-   Bytecode for `add()` stored in Method Area
-   No machine code generated yet

At this stage, JVM only has bytecode.

------------------------------------------------------------------------

## 5. How Methods Execute Initially

When method is called:

1.  Stack frame created in Stack memory
2.  Interpreter reads bytecode line by line
3.  Execution begins

This is slower but fast to start.

------------------------------------------------------------------------

## 6. What Are Hot Methods

A hot method is a method that: - Executes frequently - Crosses JVM
execution threshold

JVM keeps counters to detect this.

Example:

``` java
for(int i=0; i<1000000; i++){
    calculate();
}
```

`calculate()` becomes a hot method.

------------------------------------------------------------------------

## 7. Role of JIT Compiler

When JVM detects hot code:

1.  Bytecode is sent to JIT compiler
2.  JIT converts bytecode to native machine code
3.  Native code stored in Code Cache
4.  Next executions run faster

------------------------------------------------------------------------

## 8. Why JIT Is Needed

Interpreter: - Reads bytecode every time - Slower for loops and repeated
logic

JIT: - Converts once - CPU executes directly - Much faster

------------------------------------------------------------------------

## 9. Memory Areas Summary

### Method Area (Metaspace)

-   Class metadata
-   Method bytecode
-   Static variables
-   Constant pool

### Heap

-   Objects
-   Instance variables

### Stack

-   Method calls
-   Local variables

### Code Cache

-   Native code generated by JIT

------------------------------------------------------------------------

## 10. What Happens After JVM Restart

Important: - JIT compiled code is stored only in memory - After restart,
JVM recompiles hot methods again

This is called JVM warm-up.

------------------------------------------------------------------------

## 11. Complete Flow Diagram

    Java Source (.java)
            ↓
    Bytecode (.class)
            ↓
    ClassLoader
            ↓
    Method Area (metadata + bytecode)
            ↓
    Interpreter executes methods
            ↓
    Hot methods detected
            ↓
    JIT compiles to native code
            ↓
    CPU executes native code

------------------------------------------------------------------------

## 12. Interview Short Answer

**How class loading and JIT relate?**

A strong answer:

"ClassLoader loads classes and stores metadata and method bytecode in
Method Area. Methods initially run using the interpreter. JVM detects
frequently executed methods and sends them to the JIT compiler, which
converts them into native machine code to improve performance."
